# 首次使用与常见问题

## 首次配置

1. 首次使用初始化账号 `admin / admin123` 登录，并在用户管理中修改密码。通过应用自动初始化时会加入示例项目、客户、工单、知识和占位模型；上线前核对并清理示例记录，替换示例 Git 地址与客户环境信息。
2. 在系统设置的模型配置中填写实际模型名称、兼容接口地址和 API Key，检查连通性并设置默认模型。初始化的网关地址只是占位值。
3. 维护项目及代码仓库，按需配置 Git 凭据；维护客户、部署版本、资料及 SSH 环境，然后拉取客户代码。
4. 创建团队用户并分配角色和客户。内置管理员可访问全部客户；工程师和只读角色默认仅访问分配的客户，具体操作受角色权限控制。
5. 新建售后记录，在工作区描述现象并提交日志或附件，选择相应排查模式。需要复用知识时勾选“参考历史知识”（默认关闭）。
6. 查看工具执行过程、证据与结论，核对待审批的具体操作；完成后关闭工单，按需沉淀知识。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 页面或 API 无法访问 | 查看 Compose 状态、应用日志与 `/health`；健康接口成功不代表模型或 SSH 可用 |
| 数据库启动失败 | 检查端口 5432 是否被占用、卷是否存在、密码是否与初始化时一致 |
| 修改配置后管理员密码没变 | 管理员账号保存在数据库中，不是运行时配置；使用有权限的账号在用户管理中修改 |
| Agent 提示模型配置错误 | 替换示例网关，检查模型是否启用、模型名称、API Key 和网络连通性 |
| 用户看不到客户或工单 | 检查角色数据范围、客户分配和操作权限 |
| Git / SSH 失败 | 检查仓库地址、分支、凭据、客户环境地址和服务端网络；容器内路径与宿主机路径不同 |
| PDF 没有可提取文本 | 当前不自动 OCR，扫描件应先转成文本或带文本层的 PDF |
| 密钥文件损坏或历史凭据无法解密 | 恢复匹配的数据库与密钥备份，勿直接删除 `_secrets.json` |

上传文件、知识文档和排查产物依赖运行数据目录，迁移机器时必须与数据库一起迁移。更多运维操作见 [部署说明](docker/README.md)。
